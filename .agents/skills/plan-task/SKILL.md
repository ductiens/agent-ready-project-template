# Plan a task

1. Read the request, nearest `AGENTS.md`, project specification, architecture, manifests, tests, and CI.
2. Identify expected behavior, non-goals, constraints, affected modules, risks, and validation evidence.
3. Ask one concrete blocking question when a material decision is missing. Do not edit while blocked.
4. Otherwise produce a short ordered plan with files or areas to inspect, implementation steps, tests, and approval points.
5. Revise the plan when repository evidence invalidates an assumption.

A plan is not complete unless success can be verified objectively.
